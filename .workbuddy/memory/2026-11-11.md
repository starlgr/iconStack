## iconStack 图标管理系统 — 方案与选型（尚未写业务代码）

- 需求：Vue3 + Vite 后台式图标管理系统，应用 frontend-design 设计技能。上传图片并自定义命名、左侧分类管理、批量删除/批量移动、完整清晰展示图标与尺寸。用户要求先给方案与页面结构、先确认不明确点。
- 设计方向（frontend-design）：主题「图标打样台 / 资产档案柜」，刻意避开 AI 三种默认长相（暖米色衬线 / 近黑+荧光绿 / 报纸分栏）。
  - 色板：#0E1620 工作区底 / #182430 面板 / #E8EDF2 图纸白预览底板 / #5B9DFF 钴蓝交互 / #D9A05B 铜色尺寸标注 / #9FB3C4 次级文字
  - 字体：Space Grotesk（标题）+ Inter / Noto Sans SC（正文）+ JetBrains Mono（尺寸、体积、编号）
  - 签名元素：打样底板 + 规格尺（W×H 标签、1:1 虚线框），解决透明图标在深底不可见与缩放误判尺寸
  - 布局：三栏（左分类树 / 中打样网格 + 批量浮条 / 右详情检视），右栏可折叠
- 用户确认的 4 项选型：
  1. 存储：**本地 Node(Express) 服务 + 磁盘文件目录 + 元数据 JSON**，不是纯前端 IndexedDB，也不是纯 mock UI
  2. 格式：PNG / SVG / JPG / WebP / GIF 全支持；位图读 naturalWidth/Height（服务端用 image-size），SVG 解析 viewBox / width-height
  3. 分类：**单层 + 「未分类」兜底**，删除分类时其下图标 categoryId 置空，不级联删除
  4. 附加能力：搜索/筛选/排序、复制 SVG 源码/下载/改名（含替换文件）、整库导出/导入 ZIP 备份
  5. 未勾选「三底板切换 / 1:1 标尺」→ 只保留浅色打样底板 + 尺寸标注 + 详情面板「适应/原始大小」单一开关，不铺开完整标尺系统
- 技术架构草案：Vite 前端 + Express 后端（/api 走 vite proxy），`server/data/library.json` 存元数据、`server/uploads/` 存原文件；library.json 写入需串行队列 + 原子写（tmp→rename）；磁盘文件以 id 命名避免路径穿越；ZIP 用 archiver/yauzl；`concurrently` 一键起双服务。
- 状态：方案 v1 已交付并确认选型，等待用户下达开始指令后实施。

## EADDRINUSE 排障（14:50）

- 现象：用户本地 `npm run start` 报 `EADDRINUSE 0.0.0.0:3001`，其环境 Node v18.10.0。
- 根因：为实时预览启动的后台 `npm run dev`（concurrently）一直占用 3001 与 5173，用户又单独启动了后端。已 TaskStop 停掉，确认 3001 / 3101 / 5173 全部空闲。
- 代码改进：`server/index.js` 给 `server` 加 `error` 监听，EADDRINUSE 时输出中文排查指引（查 PID 或换 PORT）并 `exit 1`，不再抛未捕获堆栈；启动日志补充「页面入口」与 dist 缺失提示。`vite.config.js` 的 proxy target 改为跟随 `process.env.PORT`，换端口时前后端仍对齐。
- Node 18 兼容验证：用系统 Node v18.20.4 跑 `vite build` 通过；以 `PORT=3101` 启动后端，bootstrap（12 图标 / 4 分类）与 SPA 首页均 200。
- 运行约定：`npm run start` = 仅后端 :3001 并托管 dist（访问 :3001）；`npm run dev` = 双进程（访问 :5173）。**二者不可同时运行**，否则两个进程会并发写同一份 `server/data/library.json`。
